## 它怎么工作的

懒人听书的音频地址接口 `batchGetListenPath` 需要签名参数 `sc`，而 `sc` 由 App
内被加固的安全库在运行时生成，**无法静态计算**（相关签名函数在二进制里做了混淆/加固）。

但实测发现一个关键事实：

> **`sc` 只对 URL 的公共 query 参数签名，不覆盖 POST body。**

所以只要从 App 的真实请求里拿到**一个新鲜的 `sc`**，就能**复用它**、任意修改请求
body 里的 `sections`，一次拉最多 50 集的音频直链，翻页即可下载整本 —— **完全不需要
自己计算签名**。

工具围绕这个思路构建：

1. **抓 `sc`（一次性）**：用 mitmproxy 插件记录 App 发出的一条 `batchGetListenPath`
   请求（只记录，**不下载**）。同时顺手把 App 的目录接口响应（`bookInfoPage` /
   `ClientGetBookResource`）缓存下来，供命名使用。
2. **批量下载**：读那条请求里的 `sc`，自己构造 body、翻页拉直链、并发下载、断点续传。
3. **按章节名归档**：优先用抓包缓存的目录命名（`第N集_章节名.m4a`），下载完成后自动
   自检并修复书名 / 章节名。

## 特性

- ✅ **下载/改名零第三方依赖**（只需 Python 3.9+ 标准库）；只有「抓 sc」需要 mitmproxy
- ✅ **一键抓包**：`grab_sc.py` 自动开关系统代理、起停 mitmproxy、检查/引导安装证书，
  抓到 sc 后**自动进入下载**，全程一条龙
- ✅ **断点续传**：已存在的集自动跳过，重跑只补缺的；**绝不删除已有音频**
- ✅ **逐集实时日志**：每集下完立即打印（✔成功 / ·跳过 / ✘失败，带全书进度）
- ✅ **失败可追溯**：失败集号写入 `_failed.txt`，重跑自动补下
- ✅ **单集 + 整批双重试**：网络抖动不丢集
- ✅ **自动命名**：`第N集_章节名.m4a`，与 App 显示一致；自动清理标题里的引流广告
- ✅ **下载后自检**：自动检查书名目录（`book_123` → 真书名）与每集章节名（纯 `第N集`
  → 补标题），修不了的明确提示
- ✅ **目录多源兜底**：抓包缓存 → `getBookMenu` → `--no-menu`，接口风控也能下
- ✅ **不重复下载**：抓包只记录不下载，避免和下载器撞车重复拉流

## 目录结构

```
lrts-downloader/
├── cli.py                # 命令行入口（dl / rename / menu）
├── grab_sc.py            # 一键抓 sc：检查证书→起 mitmproxy→开代理→抓包→关代理→自动下载
├── lrts/
│   ├── __init__.py
│   ├── common.py         # HTTP 重试、目录抓取+缓存、命名清洗、书名获取
│   ├── certsetup.py      # mitmproxy 证书检测 + 引导安装
│   ├── download.py       # 批量下载核心（断点续传/重试/失败记录）
│   └── rename.py         # 按章节名重命名 + 下载后自检修复
├── addons/
│   └── sniffer.py        # mitmproxy 插件（记录 sc；缓存目录与书名；不下载音频）
├── data/                 # 运行产物（已 gitignore，本地数据不进仓库）
│   ├── samples/          # req_samples.jsonl（抓包样本）、menu_/name_（缓存）
│   ├── cache/            # 目录缓存
│   └── audio/            # 下载的音频（<书名>/第N集_章节名.m4a）
├── requirements.txt
├── LICENSE
└── README.md
```

## 快速开始（三步）

### 1) 一键抓 sc 并自动下载

```bash
cd lrts-downloader
python grab_sc.py
```

脚本会**全自动**完成：

1. 检查 mitmproxy 证书（没有就生成并**引导你安装信任**，装一次以后不再问）
2. 启动 mitmproxy、开启系统代理（会提示输 sudo 密码）
3. 提示你：**打开懒人听书 App，点任意一集播放几秒**
4. 抓到请求后 → **自动关闭代理、停止 mitmproxy**（用 `try/finally` 保证不会把你搞断网）
5. **自动进入下载**：问你「1 全本 / 2 自定义范围」，选完开始下载

### 2) 在 App 里播一集

看到提示后，去 App 点开目标书、播放任意一集（几秒即可），剩下的交给脚本。

> 💡 **想让全书集都有章节名**：播放的同时，可以在 App 的**目录页多向下滑几页**（滑到
> 你想要的集数附近）。程序会顺便把 App 返回的目录缓存下来，下载后文件命名更完整。
> 这是纯被动抓取（抄 App 自己的请求），**不会给接口额外增加请求、不会触发限流**。

### 3) 等下载完成

下载时会**逐集打印日志**，例如：

```
[*] 目标 1..1853（共 1853），每批 50，并发 8
    ✔ 第1集  第1集_片花.m4a  0.24MB  [总 1/1853]
    ✔ 第2集  第2集_全球高武.m4a  6.03MB  [总 2/1853]
    · 第3集  已存在，跳过  [3/1853]
    ✘ 第974集  失败：HTTP 502   （会记入 _failed.txt，重跑自动补）
...
[*] 自检书名与章节名…
  [自检] ✔ 书名与章节名正常（1853 集，1853 集带章节名）
[*] 目录: data/audio/全球高武|多人有声剧|热播动漫原著
```

产物在 `data/audio/<书名>/第N集_章节名.m4a`。

## 命令详解

### `grab_sc.py` — 一键抓 sc + 自动下载

```bash
python grab_sc.py                       # 默认 :8080、Wi-Fi
python grab_sc.py --port 8080 --service "Wi-Fi" --timeout 180
python grab_sc.py --confdir ./my-certs  # 指定 mitmproxy 证书目录
```

| 参数 | 说明 |
|---|---|
| `--port` | mitmproxy 监听端口（默认 8080） |
| `--service` | 系统网络服务名（macOS，默认 `Wi-Fi`） |
| `--timeout` | 等待你播放的最长秒数（默认 180） |
| `--confdir` | 证书目录（默认项目内 `.mitmproxy/`，不依赖系统其他证书） |

### `cli.py dl` — 只下载（已有 sc 时用，不再抓包）

```bash
python cli.py dl --book 43913               # 交互选范围
python cli.py dl --book 43913 --start 100 --end 200
python cli.py dl --book 43913 --dry         # 空跑探测，不下载
python cli.py dl --book 43913 --name "全球高武"   # 书名抓不到时手动指定
python cli.py dl --book 43913 --no-menu     # 跳过目录，按 section 下，命名 第N集
```

- `--book`：书号（8 位数字，可从 App 分享链接/URL 里看到）
- 终端下会交互询问下载范围；**非交互环境**（脚本/管道/CI）自动按参数执行、默认全本

### `cli.py rename` — 单独补全/重命名章节名

**下载后想单独补章节名**（比如之前用 `--no-menu` 只下了 `第N集.m4a`，后来想补标题），
用这条命令即可，不必重下：

```bash
python cli.py rename                # 处理 data/audio 下所有书
python cli.py rename --book 43913   # 只处理某本（推荐，最准确）
```

- 它按当前缓存/在线目录把 `第N集.m4a` 补成 `第N集_章节名.m4a`，**只改名，不动音频**
- 已正确的、缺章节名的会跳过，**幂等安全**
- 拿不到章节名时会提示你去 App 多滑几章再重试
- 对没有 `_manifest.json` 的旧目录，也可用 `--book <书号>` 指定后处理

> 补全章节名的**来源**：优先抓包缓存（`data/samples/menu_<书号>.json`），其次在线
> `getBookMenu`。所以想在 App 里多滑几章目录、再跑这条命令，就能补得最全。

### `cli.py menu` — 查看目录 / 验证缓存

```bash
python cli.py menu --book 43913 --show 20
```

## 数据存放与保护

- 所有产物在 `data/` 下，**已加入 `.gitignore`**，不会误传：
  - `data/audio/<书名>/` —— 下载的音频
  - `data/samples/` —— 抓包样本（`req_samples.jsonl`）与目录/书名缓存（`menu_*` / `name_*`）
- **下载是纯增量的**：已存在的集一律跳过，工具**从不主动删除**已下载的音频。
- `_failed.txt`：记录失败集号；重跑同一命令会自动补下。
- `_manifest.json`：每本书的元信息（书名、bookId、集数、大小）。

> 💡 建议把 `data/audio` 定期备份到别处；工具本身不会删你的文件，但误操作/磁盘故障另说。

## 常见问题

**Q：提示 `非法请求AA` / `status=114`（目录接口被限流）？**
这是 `getBookMenu`（H5 目录接口）的 IP 频率风控——连续翻几十页会被临时封，几十分钟后自动解除。

**推荐解决办法（不限流）：打开 App 这本书，在目录页向下多滑几章**（滑到你要下载的集数
附近），程序会从 App 自己的请求里被动缓存章节名（App 正常流量，不会额外请求、不会再被封），
然后再运行下载 / 或 `python cli.py rename --book <书号>` 即可。

其它兜底：
- 抓 sc 时 sniffer 也会缓存目录响应到 `data/samples/menu_<bookId>.json`，下载优先用这份。
- 实在拿不到章节名，可用 `--no-menu` 先下音频（命名 `第N集`，音频不受影响），稍后补标题。

**Q：提示 sc 可能过期？**
App 的 sc 有效期通常 ≥1 小时（实测 3 小时前抓的仍可调 App 接口）。若下载报 483，
重新 `python grab_sc.py` 在 App 播一集即可。

**Q：为什么一次最多 50 集？**
服务端限制，超过返回 `size过大`。工具已自动按 50 一页翻页。

**Q：下载的音频能正常播放吗？**
能，是标准 M4A（`ftyp` 头）。下载器会校验体积，过小（疑似空/损坏）记为失败。

**Q：目录名 / 文件名里的 `|` 是什么？**
书名常带演播信息，形如 `书名|演播|类型`。`|` 是 macOS/Linux 合法文件名字符，故保留。

**Q：为什么有的集只有「第N集」没有章节名？**
有的书本身就没有副标题（尤其前几集的引流广告），或目录数据不全。下载后自检会尽量补；
补不了的会提示，可稍后 `cli.py rename` 再试。

**Q：抓包/sc 依赖 iOS App 吗？**
需要能拿到 App 的真实请求（即需要 App 在线播放一次）。这是 `sc` 唯一可靠的来源。
拿到 sc 后的下载完全由本工具独立完成，不再依赖 App。
